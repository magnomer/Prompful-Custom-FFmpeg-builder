빌드 과정의 투명성

Promptful Custom FFmpeg Builder는 FFmpeg나 코덱 라이브러리, 또는 빌드 환경과 함께 배포되지 않습니다. 또한 빌드 시작 전에 실행 계획을 확인할 수 있도록 설계되어 사용자가 선택한 로컬 작업 폴더에 개인용 빌드 환경을 준비하고, 검토 가능한 실행 계획을 수립한 후, 사용자의 승인을 받은 작업만 실행합니다. 빌드 작업 내용도 이후에 확인할 수 있도록 로그와 보고서를 제공합니다.

이 문서는 빌드 과정에서 어떤 정보가 표시되고, 그 정보가 어떤 방식으로 확인 가능하며 기록되는지를 다룹니다.

확인 가능한 정보

검토 대상인 작업에 대해서는 다음 정보가 표시됩니다.

  • 검토 대상인 작업의 종류
  • 다운로드 URL과 검증 정보
  • 압축 해제 대상 위치
  • 설치할 MSYS2 패키지
  • 선택된 라이브러리와 생성된 configure 플래그
  • 사용자가 직접 입력한 configure 플래그
  • 생성된 스크립트와 스크립트 해시
  • 잠재적 문제의 심각도 및 경고
  • 라이선스
  • PATH 변경, 관리자 권한 필요 여부, 기존 MSYS2 사용 여부, 파일 삭제 여부

UI는 이러한 정보를 화면에 표시하나, 실제 실행 시에는 검토 대상인 작업에 대해 백엔드가 다시 확인한 후 윈도우 네이티브 확인 창으로 사용자의 승인을 받습니다.

빌드 실행 전 계획 검토

이 프로그램은 실행 계획을 먼저 수립하고, 사용자가 그 계획을 검토한 후에야 빌드를 실행하는 방식을 사용합니다. 즉, 빌드를 일단 시작한 후에 상황을 보고하는 방식이 아닙니다.

계획 검토 단계에서는 빌드 작업이 시작되기 전, 어떤 패키지가 설치되는지, 어떤 소스 아카이브를 다운로드받는지, 어떤 configure 플래그가 쓰이는지, 어떤 스크립트가 생성되는지, 어떤 라이선스를 갖게 되는지 등에 대한 정보를 사용자에게 제공합니다.

로컬 작업 폴더

이 프로그램은 사용자가 선택한 로컬 작업 폴더 내에서 작업합니다. 다운로드 파일, 압축 해제 결과, 생성된 스크립트, 로그, 보고서, 개인용 MSYS2 파일, 최종 빌드 복사 등은 모두 로컬 작업 폴더 내에서만 이루어지도록 관리됩니다.

사용자가 빌드 실행 계획에 동의했다고 해서 경로 검사가 생략되지는 않습니다. 실행 계획에 대한 동의는 계획된 작업을 사용자가 승인했다는 것일 뿐, 이 프로그램은 작업 과정에서 어떤 파일이나 폴더가 실제로 기록되고, 복사되고, 삭제되는 내용을 감시하고 제한합니다.

다운로드와 소스 검증

다운로드 역시 검토 계획에 표시됩니다. 이 프로그램은 다운로드에 대해 URL, 저장 위치, 사용 가능한 검증 정보 등을 기록하며, 다운로드 과정에서 HTTPS 사용 여부, 작업 폴더 내 저장 위치, 파일 크기, URL에 대한 리다이렉트 감시, 선택적 SHA-256 검증, 계획에 포함된 서명/키 다운로드 등을 감독합니다. MSYS2 패키지 설치 스크립트는 순서가 정해진 패키지 미러 목록과 전송 제한이 있는 curl 명령도 설정하여 한 미러가 멈춘 경우 다른 미러로 넘어갈 수 있게 합니다.

스크립트

이 프로그램은 FFmpeg 빌드 과정에서 패키지 설치, configure, make, 일부 준비 라이브러리 작업을 위해 셸 스크립트를 사용합니다. 작업 폴더 내에 해당 스크립트를 작성하고, SHA-256 해시를 기록합니다. 그리고 생성된 스크립트를 실행하기 전에는 파일 내용을 다시 확인하여 스크립트가 이전에 승인된 해시와 다른 해시를 가지고 있을 경우 해당 스크립트를 실행하지 않습니다. 이를 통해 스크립트 내용 역시 검토된 빌드 범위 안에서 작동하도록 관리됩니다.

일부 항목의 경우 호환성을 위해 별도 생성된 configure 스크립트 내에서 몇 가지 처리가 이루어집니다. 예를 들어 --enable-libsvtjpegxs, --enable-liblensfun, --enable-vapoursynth 같은 플래그는 별도 검사를 거친 뒤, 선택한 FFmpeg 소스에서 요구되는 API를 제공하는 패키지를 구할 수 없을 경우 경고를 남기고 배제될 수 있습니다. FFmpeg 9에서는 --enable-libonnxruntime 선택 시 MSYS2의 별도 ONNX Runtime 헤더 경로를 추가하며, configure 전에 AMF 1.5.2.0 이상과 NVENC SDK 11.1 이상에 해당하는 헤더인지 확인합니다.

실행 계획

패키지 설치나 실제 빌드와 같은 중요 작업은 별도로 관리되는 실행 계획을 통해 관리됩니다. 이 실행 계획에서는 실행 파일 경로, 작업 디렉터리, MSYS2 루트, 로그 디렉터리, 실행 파일 이름, 생성된 스크립트 해시 등을 감시 및 관리합니다.

일시적인 네트워크 오류만 반복되어 명령의 재시도 횟수를 모두 소진한 경우에는 일반 실패와 다른 stalled 상태를 기록합니다. 이때 실행은 더 이상 진행 중으로 보지 않지만 일반 빌드 실패로도 기록하지 않으며, 시도했던 미러/호스트 주소를 UI에 전달합니다. FFmpeg 빌드의 경우에는 이미 승인된 같은 계획을 다시 실행하여 기존 캐시와 준비 결과를 재사용할 수 있습니다.

단, 결과 폴더를 열거나, 보고서를 열기, 저장된 로그를 열기, 설치된 패키지를 확인, 생성된 FFmpeg 바이너리 검사, 개인용 MSYS2 작업 환경 정리와 같은 보조적 성격의 작업은 중요 작업으로 간주되지 않습니다.

로그/보고서/승인 기록

이 프로그램은 사용자가 추후에 빌드 과정과 결과를 확인할 수 있는 여러 가지 기록을 제공합니다.

기록 용도
실시간 프로세스 로그 작업 실행 중 stdout/stderr를 표시합니다.
저장된 로컬 로그 기록 이전 로컬 로그와 별도로 구분되는 stalled 종료 상태를 이후 다시 확인할 수 있게 합니다.
빌드 보고서 JSON 선택된 라이브러리, 플래그, 라이선스 프로필, 출력 파일, 크기, SHA-256 해시를 기록합니다.
승인 기록 JSONL 로컬 승인과 주요 작업 이벤트를 기록합니다.

이 파일들은 로컬 환경에만 저장됩니다.

UI와 백엔드의 역할

이 프로그램에서 UI는 정보를 표시하며 사용자의 선택을 돕고, 경우에 따라서는 사용자가 사용하기 편한 언어를 제공하며, 사용자가 선택한 항목이 무엇인지 기억하고, 필요한 정보를 보여주는 역할을 합니다. 실제 빌드 생성은 백엔드가 담당하며, 백엔드는 계획 생성 및 세션 검증, 네이티브 확인 창을 통한 승인, 동의 값 생성, 다운로드, 압축 해제, 패키지 설치, 명령 실행, 보고서 작성, 로그 작성, 작업 폴더 검사 등의 주요 실제 작업을 담당하고 감독합니다.

투명성 범위

이 문서에서 설명하는 투명성이란 이 프로그램이 제공하는 모든 FFmpeg 옵션이 안전하거나, 사용 가능하거나, 선택 가능하다는 보장의 의미가 아닙니다. 이 문서는 이 프로그램이 빌드 과정에 필요한 정보를 어떻게 표시하고 기록하는지를 설명합니다.

그리고 어떠한 빌드 정보도 외부로 전송되지 않습니다. 로그, 보고서, 승인 기록은 사용자가 빌드 과정을 확인할 수 있도록 로컬에만 기록되고 저장됩니다.
