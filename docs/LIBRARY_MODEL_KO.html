FFmpeg 라이브러리 선택, 프리셋, 충돌 규칙, configure 옵션, 라이선스 영향 등을 다룬 문서입니다.

라이브러리/옵션

이 문서는 프로그램이 FFmpeg 라이브러리 선택, 내부 소스 준비, 외부 SDK/가져오기 계열 항목, configure 옵션, 프리셋, 충돌 규칙, 라이선스 경계를 어떻게 해석하는지 정리한 구현 모델 문서입니다.

사용자용 기능 소개가 아니라, 코드가 실제로 어떤 기준으로 항목을 분류하고 빌드 계획을 만드는지를 설명하는 문서입니다. 따라서 어떤 항목이 카탈로그에 존재한다는 사실만으로 일반 사용자가 바로 선택할 수 있다거나, 실제 FFmpeg configure 단계까지 안전하게 통과한다는 뜻은 아닙니다.

1. 기본 설명

라이브러리 페이지의 각 행은 단순한 체크박스가 아니며, 같은 화면에 보이더라도 어떤 행은 FFmpeg 소스에 원래 포함된 구성 요소이고, 어떤 행은 MSYS2 패키지만 설치하면 되는 선택형 라이브러리이며, 어떤 행은 빌드 전에 프로그램이 직접 소스를 준비해야 하는 요소이기도 합니다. 또 어떤 경우는 외부 SDK나 별도 가져오기 경로가 없으면 정상 빌드 항목으로 아직 다룰 수 없습니다.

현재 모델은 대략 다음 계층으로 나뉩니다.

구분 의미 일반적인 빌드 영향
FFmpeg 내장 행 FFmpeg 소스 트리에 원래 들어 있는 프로그램과 핵심 라이브러리 항상 켜져 있으며 추가 패키지나 --enable-lib... 플래그를 만들지 않음
네이티브 패키지 행 선택 시 MSYS2 패키지로 의존성을 충족하는 FFmpeg 연동 항목 패키지 목록과 configure 플래그를 추가함
내부 준비 행 프로그램이 전용 MSYS2 환경 안에서 별도 준비 절차를 수행해야 하는 항목 FFmpeg configure 전에 내부 준비 레시피를 실행한 뒤 플래그를 추가함
외부/가져오기 행 외부 SDK, 외부 빌드 산출물, 가져오기 경로 등이 필요한 항목 구현된 준비/가져오기 경로가 없으면 일반 계획에서 차단됨
UI 사용 불가 행 카탈로그에는 남겨 두지만 일반 UI에서는 잠근 항목 보통 선택할 수 없고 프리셋에서도 제외됨
프로필 사용 불가 행 특정 MSYS2 셸 프로필에서 사용할 수 없는 항목 해당 프로필에서는 비활성 또는 제외됨

여기서 external은 막연히 “외부 라이브러리”라는 뜻이 아니라 코드상의 LibraryTrackExternal을 가리키는 말입니다. 선택형 라이브러리 전체를 external이라고 부르면 현재 모델을 잘못 설명하게 됩니다.

2. FFmpeg 내장

일반적인 FFmpeg 소스 빌드에 이미 포함되는 구성 요소를 명시하기 위한 항목입니다. 사용자가 “무엇을 추가로 켰는가”뿐 아니라 “기본 FFmpeg에 무엇이 들어 있는가”도 라이브러리 페이지에서 확인할 수 있게 하기 위한 장치입니다.

현재 해당 요소는 다음과 같습니다.

  • ffmpeg-program
  • ffprobe-program
  • libavcodec
  • libavformat
  • libavfilter
  • libavutil
  • libswscale
  • libswresample
  • native-codecs
  • native-formats

이 항목들은 체크된 상태로 고정됩니다. MSYS2 패키지를 추가하지 않고, FFmpeg configure 플래그도 추가하지 않습니다. 다만 선택 목록과 보고서에는 포함될 수 있습니다. 그리고 프리셋 요약과 결과 보고서에서 “추가 라이브러리만 나열한 목록”뿐만 아니라 아니라 실제 빌드 구성 항목이 제시됩니다.

3. 라이브러리 트랙

각 라이브러리 행은 trackName을 가집니다. 이 값은 해당 항목을 어떻게 준비하고 검증할지를 결정합니다.

네이티브 트랙

native는 기본 트랙입니다. 네이티브 행은 선택된 MSYS2 셸 프로필의 패키지를 사용합니다.

예를 들어 ucrt64 프로필에서는 보통 다음 접두사를 사용합니다.

mingw-w64-ucrt-x86_64-

지원 프로필별 접두사는 다음과 같습니다.

셸 프로필 패키지 접두사
ucrt64 mingw-w64-ucrt-x86_64-
mingw64 mingw-w64-x86_64-
clang64 mingw-w64-clang-x86_64-

네이티브 행은 패키지 이름과 FFmpeg configure 플래그를 추가할 수 있습니다. 다만 모든 네이티브 행이 configure 플래그를 갖는 것은 아닙니다. 예를 들어 png처럼 패키지만 추가하고 별도의 --enable-lib... 플래그를 만들지 않는 항목도 있습니다.

내부 트랙

internal 트랙은 MSYS2 패키지 하나를 설치하는 것만으로는 빌드 준비가 끝나지 않는 항목입니다. 이런 항목은 FFmpeg configure 전에 프로그램이 별도 준비 절차를 수행해야 합니다.

현재 내부 트랙으로 모델링된 항목은 다음과 같습니다.

  • vvenc
  • xavs2
  • davs2
  • uavs3d
  • lcevc-dec
  • avisynthplus
  • mpeghdec
  • pocketsphinx
  • dc1394
  • libtls
  • quirc
  • klvanc

내부 트랙 항목은 백엔드에 준비 레시피가 있을 때만 정상 계획으로 넘어갈 수 있습니다. 준비 레시피가 없으면 플래그만 억지로 넘기지 않고 차단 경고를 냅니다.

현재 구현된 준비 레시피는 다음 항목을 대상으로 합니다.

  • avisynthplus
  • davs2
  • xavs2
  • uavs3d
  • lcevc-dec
  • vvenc
  • mpeghdec
  • quirc
  • klvanc
  • libtls

중요한 점은 “준비 레시피가 존재한다”와 “일반 사용자가 UI에서 선택할 수 있다”가 같은 말이 아니라는 것입니다. 어떤 항목은 백엔드 준비 경로가 있더라도 일반 사용자 경험이나 FFmpeg 쪽 호환성이 충분히 안정적이지 않으면 UI에서 잠겨 있을 수 있습니다.

외부 트랙

external 트랙은 외부 SDK, 외부에서 빌드된 산출물, 별도 가져오기 경로, 또는 그에 준하는 준비 모델이 필요한 항목입니다.

현재 외부 트랙으로 모델링된 항목은 다음과 같습니다.

  • libmfx
  • cuda-nvcc
  • decklink
  • smbclient
  • openvino
  • torch
  • tensorflow

이 항목들은 일반적인 MSYS2 패키지 기반 선택형 라이브러리와 다릅니다. 프로그램이 검증된 준비/가져오기 경로를 갖고 있지 않다면 일반 사용자가 선택할 수 있게 해서는 안 됩니다.

tensorflow는 백엔드에 준비 정의가 존재하지만, 현재 일반 UI에서는 비활성화되어 있습니다. 준비 정의가 존재하는 것만으로 정상 지원 항목인 것은 아닙니다.

4. 라이브러리 정보

라이브러리의 각 행에는 다음과 같은 정보가 포함되어 있습니다.

  • libraryId
  • 트랙 이름
  • 표시 이름
  • 카테고리
  • FFmpeg configure 플래그
  • MSYS2 패키지 이름
  • 라이선스 영향
  • 공식 웹페이지 주소
  • 일반 설명
  • 기술 설명
  • 기본 선택 여부 또는 잠금 여부

빌드 계획은 이러한 정보를 바탕으로 패키지 설치 목록, 내부 준비 필요 여부, configure 플래그, 경고, 라이선스 프로필을 계산합니다. 같은 카탈로그를 사용해 UI는 라이브러리 페이지, 프리셋 요약, 비활성 사유, 기술 세부 정보를 보여줍니다.

5. 선택 불가능 항목

어떤 항목이 카탈로그에 들어 있다는 사실은 그 항목이 일반 UI에서 바로 선택 가능하다는 의미가 아닙니다. 이 프로그램은 알려진 항목을 완전히 삭제하기보다, 필요하면 보이되 빌드가 불가능할 경우 UI에서 잠그는 방식을 사용합니다. 이를 통해 “프로그램에 등록되지 않은 항목”과 “등록되어 있으나 지금은 정상 지원하지 않는 항목인지”가 구분됩니다.

UI에서 잠긴 행

현재 일반 UI에서 보이지만 선택할 수 없도록 잠긴 항목은 다음과 같습니다.

  • lensfun
  • svtjpegxs
  • vapoursynth
  • tensorflow
  • onnxruntime

이 항목들은 숨겨진 것이 아닙니다. 목록에 남아 있으며, 왜 일반 선택 항목이 아닌지 설명을 제공하기 위한 항목들입니다. 자동 프리셋에서는 제외됩니다.

정상 빌드 경로가 아직 없는 행

다음 항목들은 카탈로그에 있지만 일반적인 빌드/준비 경로가 아직 구현되어 있지 않은 항목입니다.

  • smbclient
  • openvino
  • torch
  • libmfx
  • pocketsphinx
  • dc1394
  • decklink
  • cuda-nvcc

일반 사용자는 이 항목을 체크할 수 없습니다. 백엔드는 구현된 준비 경로가 없는 비네이티브 항목을 정상 계획으로 인정하지 않습니다.

프로필에 따라 사용할 수 없는 행

일부 항목은 특정 MSYS2 셸 프로필에서만 사용할 수 없습니다. 이 정보는 UI와 백엔드 양쪽에서 별도로 관리됩니다.

현재 모델링된 프로필 사용 불가 항목은 다음과 같습니다.

라이브러리 사용할 수 없는 프로필
onnxruntime mingw64

백엔드 카탈로그에서는 활성 프로필에 맞지 않는 행이 제외됩니다. UI에서는 UI의 사용 불가 표시 정보을 통해 해당 항목을 사용 불가로 표시합니다.

onnxruntime은 단순히 mingw64 패키지가 없어서만 잠긴 항목이 아닙니다. 현재 이 프로그램의 원칙은 공식 FFmpeg 공식 릴리스 소스를 그대로 사용하는 것으로, ONNX Runtime DNN 백엔드 경로는 아직 일반적인 공식 공식 릴리스 소스 기반 지원 항목으로 다루기 어렵습니다.이 항목은 단순히 패키지의 문제만은 아닙니다.

6. configure 스크립트 단계의 호환성 폴백

일부 취약한 항목은 UI에서 잠겨 있지만, 기존 선택 상태나 수동 플래그, 향후 호환성을 위해 백엔드 카탈로그에는 남아 있습니다.

현재 이 방식의 특별 처리가 있는 항목은 다음과 같습니다.

  • svtjpegxs
  • lensfun
  • vapoursynth

계획 단계에서 미리 플래그를 제거하지는 않습니다. 해당 configure 플래그가 생성된 FFmpeg configure 스크립트까지 도달하면, 스크립트가 최종 ./configure 호출 전에 작은 호환성 검사를 수행합니다. 설치된 패키지가 선택된 FFmpeg 소스가 요구하는 API를 제공하지 않는다고 판단되면, 스크립트는 해당 플래그만 제거하고 경고를 출력한 뒤 관련 pkg-config 진단을 건너뛰고 계속 진행합니다.

즉 세 항목에 대해 제한적인 예외 처리를 하는 것으로, UI에서 잠긴 모든 라이브러리나, 사용 불가로 표시된 모든 라이브러리에 적용되는 일반 규칙이 아닙니다. 예를 들어 tensorflow와 onnxruntime에는 동일한 검사 후 동일한 진단이 내려지지 않습니다.

7. 라이브러리 프리셋

라이브러리 프리셋은 UI의 선택 템플릿입니다. 백엔드 카탈로그 자체를 대체하지 않습니다.

공개 확장형 프리셋

일반 UI에서 사용하는 공개 프리셋은 다음과 같습니다.

  • minimal
  • default
  • efficiency
  • compatibility
  • editor
  • full
  • custom

공개 확장형 프리셋은 단계적으로 확장되는 구조입니다. 높은 단계는 낮은 단계의 선택을 바탕으로 일반적으로 더 많은 항목을 추가합니다.

프리셋 의미
minimal FFmpeg 내장 행만 포함
default 일반적으로 자주 쓰는 코덱, 오디오 보조 기능, 자막/폰트, 하드웨어 가속, 프로토콜/필터 지원을 포함
efficiency default에 품질과 효율을 위한 AAC/resampling 계열 선택 등을 추가
compatibility 코덱, 자막, 캡션, 프로토콜 호환 범위를 더 넓힘
editor 편집, 필터링, 색상, 오디오 분석, 자막, 전사 작업에 가까운 항목을 추가
full 상호 배타 항목을 정리한 뒤 일반적으로 패키지 기반으로 넓게 선택할 수 있는 최대 범위
custom 현재 선택 상태가 특정 프리셋과 정확히 일치하지 않을 때 표시되는 상태

프리셋을 적용해도 일반 선택 가능 항목은 이후 사용자가 다시 켜거나 끌 수 있습니다. 내장 행은 계속 선택된 상태로 고정됩니다.

Extended 프리셋 모드

Extended는 별도의 프리셋 ID가 아닙니다. 기존 확장형 프리셋에 내부 준비 또는 소스 준비 계열 항목을 더하는 모드입니다.

현재 Extended 추가 항목은 다음과 같습니다.

프리셋 Extended 추가 항목
efficiency vvenc, uavs3d, lcevc-dec
compatibility davs2, uavs3d, lcevc-dec, avisynthplus, xavs2
editor avisynthplus, lcevc-dec
full vvenc, xavs2, davs2, uavs3d, lcevc-dec, avisynthplus, mpeghdec

Extended를 켜면 라이선스도 달라질 수 있습니다. 예를 들어 xavs2, davs2, avisynthplus는 GPL 효과를 만들 수 있고, mpeghdec는 nonfree 효과를 만듭니다.

숨겨진 목적형 프리셋

UI는 일반 프리셋 UI에 보이지 않는 목적형 프리셋도 정의합니다.

  • ai
  • streaming

이 둘은 단계적으로 확장지는 공개 프리셋이 아닙니다. default에 각각의 목적에 맞는 항목을 더하는 방식입니다. 즉 efficiency, compatibility, editor, full과 별개 프리셋입니다.

8. 상호 배타 선택

일부 라이브러리는 동시에 선택할 수 없습니다. FFmpeg configure가 조합을 거부하거나, 같은 역할에 대해 서로 다른 바인딩을 의미하기 때문입니다.

현재 상호 배타 그룹은 다음과 같습니다.

그룹 구성원 규칙
TLS 백엔드 openssl, gnutls, mbedtls, libtls 보통 하나만 선택
런타임 셰이더 컴파일러 shaderc, glslang 최대 하나 선택
EVC 디코더 바인딩 xevd, xevdb 프로필 바인딩 하나 선택
EVC 인코더 바인딩 xeve, xeveb 프로필 바인딩 하나 선택

UI는 사용자가 항목을 켜고 끌 때 발생할 수 있는 충돌을 사전에 처리합니다. 계획 단계에서도 최종 configure 플래그 목록을 다시 검사하며, 상호 배타 플래그가 백엔드까지 도달하면 차단 경고를 냅니다.

9. 빌드 계획

FFmpeg 빌드 계획기는 선택된 라이브러리 ID, configure 옵션 ID, 추가 configure 플래그, 소스 설정, 작업 공간 설정, 셸 프로필, 병렬 작업 수를 입력으로 받습니다.

계획 단계는 대략 다음 순서로 진행됩니다

  1. 입력 설정을 정리합니다.
  2. 선택된 라이브러리 ID를 활성 카탈로그와 대조합니다.
  3. 선택된 네이티브 행에서 MSYS2 패키지 설치 목록을 계산합니다.
  4. 선택된 내부/외부 트랙 행에서 준비 또는 가져오기 필요 여부를 확인합니다.
  5. 수동 configure 플래그가 카탈로그의 라이브러리 플래그와 일치하면 해당 라이브러리 효과를 복구합니다.
  6. 라이브러리 플래그, 옵션 플래그, 수동 플래그, 라이선스 파생 플래그를 합칩니다.
  7. 충돌 조합과 위험한 조합을 검사합니다.
  8. 로컬 라이선스 프로필을 계산합니다.
  9. 사용자가 검토할 수 있는 계획을 만듭니다.

MSYS2 패키지는 FFmpeg configure 전에 설치됩니다. 내부/외부 준비는 해당 configure 플래그가 최종 스크립트로 넘어가기 전에 검증됩니다.

10. 수동 configure 플래그 복구

고급 플래그 입력란은 예외 경로이지만, 무제한적으로 모든 것을 허용하는 용도는 아닙니다.

사용자가 추가한 configure 플래그가 카탈로그의 어떤 라이브러리 행이 가진 configure 플래그와 정확히 일치하고, 그 라이브러리가 아직 선택되어 있지 않다면 계획기는 그 행을 사실상 선택된 라이브러리처럼 취급합니다. 이 경우 해당 라이브러리의 MSYS2 패키지, 라이선스 영향, 내부/외부 준비 게이트가 함께 적용됩니다.

이 부분은 카탈로그 전체를 대상으로 합니다. external 트랙에만 한정되지 않습니다.

다만 이 방식은 configure 플래그가 있는 행에만 적용됩니다. 패키지만 추가하고 configure 플래그가 없는 행은 수동 --enable-lib... 플래그를 통해 사용할 수 없습니다.

11. configure 옵션 카탈로그

옵션 페이지는 라이브러리 페이지와 별도입니다. 이 페이지는 라이브러리 행이 아니라 FFmpeg 빌드 스위치를 모델링합니다.

각 옵션 행은 다음 정보를 가질 수 있습니다.

  • option ID
  • 카테고리
  • configure 플래그
  • 일반 설명
  • 기술 설명
  • 위험도
  • 기본값 또는 잠금 상태

현재 잠긴 기본값은 다음과 같습니다.

  • default-static
  • default-programs
  • default-ffmpeg
  • default-ffprobe

선택 가능한 주요 옵션은 다음과 같습니다.

  • 출력 형식: enable-shared
  • 프로그램: disable-ffplay
  • 보안/재현성: disable-autodetect, disable-network
  • 호환성: disable-asm, disable-x86asm, pkg-config-static, enable-runtime-cpudetect
  • 크기/속도: disable-doc, enable-small, enable-lto
  • 디버깅: disable-debug, disable-stripping

옵션 페이지는 --enable-gpl, --enable-nonfree, --enable-version3을 일반 체크박스로 제공하지 않습니다. 이 플래그들은 선택된 라이브러리와 최종 플래그에서 파생됩니다. 사용자가 고급 입력란에 직접 넣는 경우에도 백엔드는 이를 검사하고 그에 맞는 라이선스 경계를 계산합니다.

또한 disable-programs나 disable-ffprobe는 일반 옵션으로 제공하지 않습니다.

12. 옵션 위험도

configure 옵션의 위험도는 라이브러리의 라이선스 효과와 다른 개념입니다. UI에서 비슷한 형태로 보일 수는 있으나 다른 의미를 갖습니다. 옵션 위험도는 라이선스가 아니라 빌드 형태, 실행 결과, 성능, 휴대성에서 사용자가 예상하지 못할 변화가 생길 가능성을 나타냅니다.

현재 위험도 해석은 다음과 같습니다.

위험도 의미
높음 빌드 형태, 성능, 휴대성에 큰 영향을 줄 수 있음. 예: enable-shared, disable-asm
보통 특정 상황에서 기능이나 성능이 줄어들 수 있음. 예: disable-network, disable-x86asm, enable-lto
낮음 일반 기본값이거나 비교적 안전한 선택

enable-shared가 높은 위험도로 분류되는 이유는 외부로 연결된 DLL를 바탕으로 한 결과물을 만들 수 있기 때문입니다. disable-asm은 대부분의 SIMD 최적화를 제거하므로 성능 영향이 큽니다.

13. 옵션 프리셋

옵션 프리셋은 Library 프리셋처럼 단계적으로 상속되는 구조가 아닙니다. 각각의 의도에 맞춘 선택 프리셋입니다.

현재 옵션 프리셋은 다음과 같습니다.

  • none
  • standard
  • compact
  • portable
  • performance
  • custom

기본값은 standard입니다. 이 프리셋은 pkg-config-static과 disable-doc을 선택합니다.

enable-shared, disable-asm, disable-x86asm, disable-network처럼 빌드 결과나 기능을 크게 바꿀 수 있는 고위험 또는 문제 해결용 옵션은 일반 프리셋에 포함되어 있지 않습니다.

disable-network를 켠 상태에서 SRT, libssh, librtmp, librist, ZeroMQ, RabbitMQ-C 같은 네트워크 라이브러리를 선택하면 계획 단계에서 경고가 뜹니다. 네트워크를 꺼 버린 FFmpeg 빌드에서는 그런 연동 항목이 실질적으로 유용하지 않기 때문입니다.

14. 라이선스 프로필 계산

백엔드는 선택된 라이브러리와 최종 configure 플래그를 기준으로 로컬 라이선스 경계를 계산합니다.

현재 로컬 프로필 이름은 다음과 같습니다.

  • lgpl-local
  • gpl-local
  • nonfree-local

우선순위는 다음과 같습니다.

nonfree-local > gpl-local > lgpl-local

GPL 라이브러리를 선택하거나 --enable-gpl이 최종 플래그에 들어가면 빌드는 gpl-local로 올라갑니다. nonfree 라이브러리를 선택하거나 --enable-nonfree가 들어가면 nonfree-local이 되며, 재배포 경고가 붙습니다.

FFmpeg의 version 3 라이선스 스위치가 필요한 라이브러리는 --enable-version3을 자동으로 추가하고 경고를 냅니다. 현재 구현된 version 3 대상 목록은 다음과 같습니다.

  • opencore-amr
  • vo-amrwbenc
  • libaribb24
  • lensfun

--enable-version3은 별도의 라이선스 프로필 이름이 아닙니다. 최종 configure 플래그와 경고에 추가되는 보조 층입니다.

15. 주의

이 프로그램의 카탈로그는 일반 사용자가 바로 선택할 수 있는 항목보다 넓습니다. 알려진 항목을 아예 삭제하지 않고 남겨 둠으로써 “현재 지원하지 않는 경우”와 “프로그램에 등록되어 있지 않는 경우”가 구분되기 위함입니다.

다만 지원 범위를 말할 때는 다음 상태는 반드시 구분되어야 합니다.

  • 카탈로그에 등록되어 있음
  • UI 목록에 보임
  • 일반 사용자가 선택할 수 있음
  • 공개 프리셋에 포함됨
  • 구현된 레시피로 소스 준비가 가능함
  • 외부 SDK나 가져오기 경로로 준비 가능함
  • FFmpeg configure 플래그로 전달됨
  • 최종 FFmpeg configure에서 실제로 받아들여짐
