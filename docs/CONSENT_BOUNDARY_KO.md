# 동의 및 승인 절차

이 프로그램은 작업을 실행하기 전에 계획을 생성하고, 사용자에게 검토가 필요한 내용을 표시하며, 계획에 이상이 없는지를 확인한 후 윈도우 네이티브 확인 창을 통해 사용자에게 최종 동의를 받습니다. 즉, 윈도우 네이티브 확인 창이 아닌 UI에서 버튼을 누른다고 하더라도 다운로드나 압축 해제, 패키지 설치, 빌드 실행 등을 이행하지 않습니다.

이 문서는 해당 동의 절차에 대해 설명합니다.

## 요약

빌드 도구를 준비하거나 FFmpeg 빌드가 시작되기 전에 이 프로그램은 다음 네 가지를 확인합니다.

1. 사용자가 승인하려는 작업과 실제 승인 요청의 작업이 같은지
2. 검토 화면에 표시된 계획 해시와 백엔드에 저장된 계획이 일치하는지
3. 사용자가 확인한 동의 문구와 승인 요청의 동의 문구가 같은지
4. 백엔드가 띄운 윈도우 네이티브 확인 창에서 사용자가 `Yes`를 선택했는지

위 사항이 모두 충족된 경우에만 이 프로그램은 빌드 작업을 이행할 수 있는 동의 값을 만듭니다.

## 사용자가 검토하는 내용

검토 화면에는 선택한 소스 아카이브, 설치할 패키지, configure 플래그, 생성될 스크립트, 경고, 라이선스 영향, 예상되는 파일 작업이 표시될 수 있습니다. UI는 이런 내용을 보여주기만 할 뿐 빌드를 독단적으로 실행하지는 않습니다.

백엔드는 별도의 검토 세션을 메모리에 저장하고, UI에서 전달받은 승인 요청이 해당 세션과 정확히 일치하는지 비교합니다. 이를 통해 UI에서 잘못 전달된 경우나 WebView 호출이 변조된 경우, 승인 요청이 재사용된 경우, 로컬 RPC 호출이 다른 빌드로 인해 영향을 받는 경우 등의 오류를 예방합니다.

## 승인 과정

승인 작업은 다음 순서로 진행됩니다.

1. 백엔드가 실행 가능한 계획을 생성
2. 백엔드가 계획을 메모리 안의 검토 세션에 저장
3. UI가 계획, 경고, 최종 configure 플래그, 패키지 목록, 라이선스 영향, 동의 문구를 표시
4. UI가 검토 세션 ID, 작업 이름, 계획 해시, 동의 문구를 포함해 승인을 요청
5. 백엔드는 세션이 존재하는지, 만료되지 않았는지, 이미 사용되지 않았는지, 요청 내용과 맞는지 확인
6. 백엔드는 저장된 계획으로 계획 해시를 재계산
7. 백엔드는 저장된 계획이 실제로 실행 가능한 상태인지 확인
8. 백엔드가 윈도우 네이티브 확인 창을 호출
9. 사용자가 최종적으로 `Yes`를 선택하면 백엔드는 작업별 동의 값을 만들고 승인된 작업을 시작

## 거절/취소/승인 만료

모든 계획의 기본 승인값은 `No`입니다. 즉, 백엔드는 `Yes`가 아닌 모든 결과를 사용자의 거절로 처리합니다. `No`나 `Cancel`이 전달된 경우, Escape 키, 창 닫기, 대화상자 오류, 승인 결과가 비어있는 경우, 예상하지 못한 버튼 문자열이 전송된 경우 등 모든 경우를 `No`로 처리합니다.

사용자가 윈도우 네이티브 확인 창에서 거절을 선택하더라도 검토 세션이 곧바로 사라지는 것은 아닙니다. 계획 세션이 유효할 경우 같은 계획으로 다시 윈도우 네이티브 확인 창을 통해 확인 절차를 밟을 수 있습니다. 계획 세션은 윈도우 네이티브 확인 창을 통한 확인이 확인된 경우에는 승인 만료로 처리됩니다. 계획 검토 세션은 30분 동안만 유효하게 유지되며, 프로그램을 닫거나 프로그램을 다시 시작하면 승인되지 않은 계획 세션은 폐기됩니다.

## 승인 절차가 적용된 경우

현재 승인 절차는 로컬 환경이나 빌드 환경을 바꿀 수 있는 작업에 적용되어 있습니다.

| 적용된 작업 | `Yes` 이후 작업 |
|---|---|
| 개인용 MSYS2 도구 준비 | MSYS2 다운로드, 아카이브 압축 해제, 패키지 설치 |
| FFmpeg 빌드 | FFmpeg/소스 다운로드, 아카이브 압축 해제, 패키지 설치, 명령 실행 |

MSYS2 도구 준비 단계에서는 MSYS2의 다운로드, MSYS2 서명 파일과 서명 키 다운로드 모두에 대해 승인 절차가 함께 이루어집니다. FFmpeg 빌드의 경우에는 FFmpeg 소스 다운로드 및 FFmpeg 서명 파일, 서명 키, 필요한 라이브러리의 소스 다운로드에도 승인 절차가 같이 적용됩니다.

## 빌드 실행 중 안전장치

승인 과정은 단지 여러 보호 장치 중 하나로, 위험할 수 있는 작업에 대해서는 해당 작업의 실행 단계에서도 별도로 검사를 수행합니다.

### 다운로드

승인받은 다운로드에 대해서도 HTTPS를 사용했는지, 작업 공간 내부 대상 경로가 적절한지, 임시 파일의 위치가 잘못되지는 않았는지, 크기가 비정상적이지 않은지, 재사용되었는지, 해시 점검(SHA-256 검사)이 필요한지 등을 확인합니다. 허용 가능한 다운로드 주소 목록에 등록되지 않은 곳에서 다운로드가 이루어질 경우 경고를 표시하기도 하지만, 단순히 다운로드 주소만 확인하지는 않습니다.

### 압축 해제

압축 해제는 압축 파일과 압축을 풀 대상 폴더가 선택한 작업 공간 내에 있는지 확인합니다. 그리고 압축 해제 과정에서 파일 수와 전체 크기도 제한합니다. 올바르지 못한 경로에 압축을 해제하려고 하거나 안전하지 않은 심볼릭 링크를 형성하려고 하는 작업도 사전에 차단합니다. 즉, 실제로 압축 해제 과정에서 해제된 파일이 쓰일 수 있는 위치와 그 내용은 압축 해제 과정의 검사를 통해 관리됩니다.

### 패키지 설치와 빌드

패키지 설치 및 빌드는 별도의 계획을 통해 이행됩니다. 해당 과정에서 실행 파일의 위치, 작업 위치, MSYS2 루트, 로그 파일 위치 및 실행 파일 이름이 타당한지, 실행 파일 경로의 메타문자가 있는지, 실행에 필요한 인자에 null 바이트가 있는지 여부 등도 검사합니다. 즉, 승인되었다고 하더라도 빌드 과정에서 작업 공간 밖에서 빌드 명령이 실행되는 것을 막습니다.

### 스크립트

FFmpeg 빌드 과정에서 패키지 설치나 configure, make, 일부 라이브러리 준비 작업에 셸 스크립트가 필요한 경우에도 이 프로그램은 스크립트를 만들면서 스크립트 위치와 SHA-256 해시를 기록합니다. 실행 직전에 해당 스크립트를 다시 점검하여 내용이 승인된 해시와 다르면 실행을 중단합니다.

## 정리 작업 및 보조 작업

일부 보조 작업의 경우 빌드 계획에 해당하는 것으로 보지 않아 동의 값을 사용하지 않습니다. 예를 들어 결과 폴더를 열거나, 보고서를 열기, 로그 폴더 열기, 패키지 상태 읽기, 생성된 FFmpeg 바이너리를 검사하고 확인하기, 개인용 MSYS2 정리하기 등의 과정이 여기에 해당합니다.

정리나 삭제 작업이 필요한 경우라도 작업 공간 내에서 제한적으로 이루어집니다. 이전에 실패한 준비 작업을 정리하거나, 실패한 빌드를 정리, 유효하지 않은 결과물을 제거, 새로운 도구로 교체, 개인용 도구 제거 등은 사용자가 선택한 작업 공간 내에서만 이루어집니다. 그리고 이 경우에도 위치를 검사하는 것은 물론 드라이브 루트 경로는 거부하고 심볼릭 링크를 검사합니다.

## 요약

이 프로그램은 빌드 가능한 내용의 “표시 및 승인 요청”과 “실제 실행 허가”를 분리하여 다룹니다. UI는 계획을 표시하고 승인을 요청할 수만 있으며, 실제로 저장된 계획을 처리하고, 계획에 대한 해시를 확인하며, 네이티브 확인 창을 호출하고, 동의 값을 생성하며, 최종 실행 검사를 하는 것은 백엔드에서 처리합니다.
